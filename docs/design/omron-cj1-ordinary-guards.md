# Проверка обычных инструкций CJ1 в полной задаче

20 ноября 2026. Для CJ1M CPU21 и CJ1H-H CPU65 проверены 689 форм инструкций
в режиме BCD и 701 в binary. В изолированном процессе выполнялась штатная
компиляция задачи CX-Pdata.dll при согласованных KBase current и Program Check
Version 3.0 или 4.0. Для каждой задачи сохранены исходные инструкции с операндами,
слова до полной компиляции, выбранная версия, результат, диагностика и итоговые
машинные слова.

| Проверка | Количество |
| --- | ---: |
| Основная матрица, две модели и две версии | 5560 |
| Дополнительные контексты | 328 |
| Успешная полная компиляция | 5576 |
| Отклонённый контекст | 312 |
| Расхождения между версиями в исследованной выборке | 0 |

Команда CMP(020) #DEAD #DEAD кодирует используемый CX разделитель секций. После
LD такая инструкция оставляет условие для следующего выхода. Последовательность
LD / CMP / END отклоняется, LD / CMP / OUT / END и CMP / END принимаются.
Nautilus теперь учитывает эту особенность после разрешения операндов. Для
обычного CMP по-прежнему требуется входное условие.

Для временных реле сравнивались чтение до определения, сохранение без
последующего выхода, затем корректная последовательность LD / OUT TR /
OUT / LD TR / OUT / END. При проверке MOV обнаружена разница между передачей
в native API одного операнда с начальным пробелом и передачей лексемы T0.
Исходный текст CXT проходит токенизацию. Для него проверены восемь дополнительных
нативных результатов с лексемой T0. Журнал сохраняет также восемь результатов
с пробелом, при котором DLL выдала другой адрес.

Проверки из корня репозитория:

    python -B tools/omron-research/cj1_ordinary_guard.py
    go test ./omron/compiler -run TestNativeOrdinaryProgramGuards

Для нативного повторения --prepare-cases NEW_DIRECTORY готовит 15 партий
и три набора контрольных случаев. Запускать каждую партию штатным
Invoke-CJ1InstructionOracle.ps1 с -ProgramObjectProbe -OrdinaryGuardProbe
и явными LocalCurrentVersion, ProgramCheckVersion, TimerCounterMode. Папка
результата в общем каталоге называется MODE-BATCH-vVERSION. Для каждого
из трёх контрольных наборов добавить -OrdinaryContext complete|standalone|canonical
и назвать папку control-MODE-VERSION-CONTEXT.
Опции --capture-root DIRECTORY --corpus NEW.json.gz проверяют запись, восстановление
инструмента и полноту покрытия и сохраняют переносимый корпус. Исходные журналы
этого запуска находятся в C:/cx-proger/research/ordinary-guard-20261120-01.

Матрица устанавливает поведение перечисленных обычных инструкций в конкретных
контекстах. 312 отказов зависят от контекста. Для общего выбора версии CPU
ещё нужны случаи, где именно версия меняет решение компилятора, и аналогичная
проверка оставшихся путей FB, размещения и настроек. Физическое исполнение и
финализация при загрузке имеют отдельные критерии приёмки.
