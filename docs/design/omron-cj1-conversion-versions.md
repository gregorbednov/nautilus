# Минимальная версия CPU для преобразований STR и NUM

20 ноября 2026 года. На профилях CJ1M CPU21 и CJ1H-H CPU65 одна и та же
цепь с преобразованием проходит полную проверку программы при Program Check
Version 4.0. При 3.0 компилятор выдаёт одну ошибку, прямо указывающую на
несовместимую версию CPU. Перестановка версий KBase current и Program Check
Version показывает, что решение в исследованном пути определяется второй.
Omron относит эти шесть инструкций к функциям версии 4.0.
[Руководство по программированию W394](https://assets.omron.eu/downloads/manual/en/v3/w394_cs1_cj1_nsj_series_programmable_controllers_programming_manual_en.pdf)
и [справочник инструкций W474](https://www.omron-ap.com/data_pdf/mnu/w474-e1-13_cs_cj_nsj.pdf?id=2045).

В одной задаче использовали `LD W0.00`, одну инструкцию и `END`. Проверяли
STR4, STR8, STR16, NUM4, NUM8, NUM16 и их варианты с `@`. Для записи без
номера функции брали D100 и D200, для записи с номером (601–606) — D0 и D24.
Контрольная цепь содержала MOV D100 D200. Для каждой комбинации выполнено
по 100 проверок (25 цепей × 2 модели × 2 режима таймеров).

| KBase current | Program Check Version | Принято | Ошибка версии |
| --- | --- | ---: | ---: |
| 3.0 | 3.0 | 4 | 96 |
| 4.0 | 3.0 | 4 | 96 |
| 3.0 | 4.0 | 100 | 0 |
| 4.0 | 4.0 | 100 | 0 |

Предварительное кодирование отдельных инструкций выдало одинаковые слова
во всех версиях. В каждом отклонённом случае полная компиляция остановилась
до выдачи кода задачи. Контрольный MOV прошёл во всех 16 сочетаниях.

Команда `naut omron inspect` указывает `minimumCJ1UnitVersion` у строки
текстовой цепи. Сборка проекта с таким преобразованием завершается диагностикой
с номером строки и требованием версии. Поддержка генерации N1 для этих
инструкций остаётся открытой. Отсутствие поля у других строк означает, что
для них в этом справочнике нет записи. Аппаратное исполнение здесь не проверялось.

В каждом из четырёх пользовательских CXP в `projects` просмотрена 231 строка
инструкций в текстовых цепях. Совпадений с этими шестью преобразованиями нет.
В отдельном проекте CJ1H-H CPU65 в режиме binary инспектор указал 4.0 у
`@NUM8(605) D0 D24`, а сборка вывела путь цепи и строку 60.

## Повторение

Из корня Nautilus выполнить `python -B tools/omron-research/cj1_conversion_versions.py`.
Переносимый корпус содержит пары событий выбора версии и результата компиляции.
Проверяются обе версии, источник, операнды, слова каждого оператора,
результат целой задачи и диагностика. CLI и тестам воспроизведения CX-One не требуется.

Для повторной нативной записи использовать `Invoke-CJ1InstructionOracle.ps1`
с `-ProgramObjectProbe -OrdinaryGuardProbe` и файлом `cj1-conversion-version-cases.json`
из того же каталога. Для каждой комбинации явно задать `-TimerCounterMode`,
`-LocalCurrentVersion` и `-ProgramCheckVersion`. Назвать каталог прогона
`MODE-CURRENT-vCHECK` (например, `binary-4.0-v3.0`). Затем запустить
верификатор с `--capture-root DIRECTORY --corpus NEW.json.gz`. Первичные журналы
сохранены в `C:/cx-proger/research/cj1-conversion-versions-20261120-01/labelled-and-plain`.
