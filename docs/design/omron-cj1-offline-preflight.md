# CJ1: офлайн-проверка CPU и резервных копий программы

18 ноября 2026 года. Продолжение [аудита передачи](omron-cj1-offline-write-audit.md).
Добавлены чистые декодеры FINS, пакет `omron/commission` и CLI. Все новые
проверки выполнены локально, без CX-One, vendor DLL и обращения к ПЛК.
На действующей установке по-прежнему разрешено только чтение.

Продолжение: [проверка рецепта повторной сборкой](omron-cj1-build-reproduction.md)
позволяет подтвердить candidate-build-provenance локально. Согласованность
настроек с исходным проектом/CPU остаётся отдельным неизвестным условием.

## Первичный источник и границы декодирования

Omron W342-E1-18, раздел 5-3-15, печатные страницы 191–192
(PDF-страницы 213–214, нумерация с единицы). Локальный источник:
`research/W342.pdf`; официальный документ:
[CS/CJ/CP/NSJ Communications Commands Reference Manual](https://assets.omron.eu/downloads/latest/manual/en/w342_cs_cj_cp_nsj_communications_commands_reference_manual_en.pdf?v=9).
Идентичность актуальной сетевой редакции локальной редакции не предполагается.
Текст и изображения локальных страниц сохранены в исследовательском снимке.

Смещения ниже отсчитываются от DATA ответа 0501, без команды и end code.

| Смещение | Размер | Интерпретация |
| --- | ---: | --- |
| 0 | 20 | Модель CPU, ASCII |
| 20 | 20 | Internal system version, не unit version |
| 40 | 1 | Сырые биты DIP; семантика защиты здесь не выводится |
| 41 | 1 | Сырое значение largest EM bank |
| 80 | 2 | Размер program area, big-endian Kwords |
| 82 | 1 | IOM Kbytes |
| 83 | 2 | DM words, big-endian |
| 85 | 1 | Timer/counter size в единицах 1024 |
| 86 | 1 | EM non-file banks |
| 89 | 1 | Memory card type |
| 90 | 2 | Memory card Kbytes, big-endian |

Один Kword равен 1024 словам по 16 бит: отчёт переводит program area в
`Kwords*1024*2` bytes. Это арифметическая верхняя граница для сравнения размеров,
а не доказательство пригодности конкретного N1 для данного CPU.
Зарезервированные поля и хвост после 92 bytes не интерпретируются.
Минимальный 92-byte префикс не доказывает полноту захваченного ответа.
`DecodeIdentityData` сохраняет совместимость с прежним минимумом 40 bytes;
`DecodeCPUUnitData` требует 92. `DecodeStatusData` требует 26 bytes,
допускает PROGRAM=0, MONITOR=2, RUN=4. Сетевые команды не изменены.

Повторно разобраны сохранённые ответы от 16 ноября, без новых сетевых чтений:

| Наблюдённый CPU | Размер из 0501 | Перевод в bytes | Архивный режим |
| --- | ---: | ---: | --- |
| CJ1M_CPU21 | 10 Kwords | 20480 | RUN |
| CJ1H_CPU65H | 120 Kwords | 245760 | RUN |

Это исторические наблюдения, не текущее состояние устройств. Внутренние NUL
в version сохраняются; несколько значений не превращаются в unit version.
В Git включён только явно обозначенный префикс 0501 и статус, с хешами
исходного снимка/полного payload. Полные аппаратные UM остаются вне Git.

## Поведение preflight

```sh
naut omron preflight-program-write -model "CJ1M CPU21" -snapshot status.json -backup um-first.bin -backup-check um-second.bin candidate.n1
```

`status.json` использует прежний формат команды status: объекты `cpu` и `status`
с сырыми ответами `raw` в base64 и текстовой/числовой сводкой.
Факты декодируются заново из raw. Несовпадение сводки блокирует проверку;
сводка не может подменить сырую модель или RUN на PROGRAM.

Поддержаны только точные наблюдённые соответствия `CJ1M_CPU21` → `CJ1M CPU21`
и `CJ1H_CPU65H` → `CJ1H-H CPU65`. Модель сборки задаётся явно: содержимое
N1 и его SHA-256 сами по себе не удостоверяют настройки компилятора.

Проверяются модель, архивный PROGRAM, отсутствие fatal/nonfatal полей,
арифметическая граница размера и две копии программы. Обе копии должны
разбираться как поддерживаемый N1 и совпадать побайтно. Равные повреждённые
файлы не проходят; файл кандидата не изменяется. Совпадение копий не доказывает
независимость чтений: допустимо передать один путь дважды, но это даёт только
равенство файлов. Копии UM не включают полный набор settings/I/O/data.

JSON содержит для каждой проверки `passed`, `blocked` или `unverified`.
Ненулевой exit code сопровождает валидный отчёт с препятствиями.
Некорректный вход отвергается без отчёта. Предел JSON — 1 MiB, каждого
N1/backup — 16 MiB; неизвестные поля и дополнительные JSON-значения запрещены.
Нет endpoint, execute, смены режима или флагов ручного обхода проверок.

Следующие условия остаются `unverified` во всех текущих сценариях:

- Подлинность и свежесть наблюдения, актуальные маршрут/SID/устройство.
- Точный unit-version profile и соответствие явных настроек проекту/CPU.
- Полное соответствие N1 целевому размещению, защите и финализации CPU.
- Полный backup и квалифицированная процедура восстановления.
- Начальные значения, размещение и аудит затрагиваемой памяти.
- Изоляция стенда и разрешение оператора на запись.

Поэтому `readyForWrite`, `hardwareQualified`, `writeQualified`, `networkAccess`
остаются false даже при благоприятных синтетических входах. Это частичная
оценка сохранённых фактов, не готовый online preflight и не загрузчик.
Изоляция исполнительных механизмов сейчас не разблокирует эти офлайн-задачи.

## Проверка и передача

Go-тесты воспроизводят оба реальных префикса, единицы измерения, внутренние NUL,
владение raw-буферами и сохранение непрозрачного хвоста. Проверены неверная
модель, конфликт сводки/raw, нулевая/малая ёмкость, разные и повреждённые backup,
неполные ответы и искусственный PROGRAM, который не разрешает запись.

Отдельная CLI-проверка использует две архивные пары UM (12380 и 2880 bytes)
и шесть явно синтетических вариантов. Все восемь сценариев сохраняют запрет
записи. Полный набор `./omron/...`, Omron CLI и `go vet` проверяются локально.
Материалы: `research/hardware/20261118-cj1-preflight-01`, включая источники,
команды, stdout/stderr, журнал тестов и SHA-256 manifest.

Далее: связать артефакт сборки с моделью/настройками, исследовать точный
unit-version profile и соответствие памяти/финализации; определить состав
полного backup. Привязка к живому маршруту, управление доступом/режимом,
транспорт записи и восстановление требуют отдельной реализации и последующей
аппаратной проверки. См. [актуальные этапы](omron-cj1-readiness-2026-11-18.md).
