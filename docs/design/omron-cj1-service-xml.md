# XML сервисов загрузки CJ1

Теперь доступен также `--family task` для отдельных сервисов463/526;
[различие task и полной передачи](omron-task-versus-program-dispatch.md).

Следующее уточнение: [IsExtendedProtect и предикат выбора передачи](omron-extended-protection-dispatch.md).

Установленные описания обоих проектов содержат **два отдельных сервиса**:
`3 / CDM_DOWNLOAD_PROGRAM` и `532 / CDM_DOWNLOAD_PROGRAM_EX`. Их версии —
`0.0.0` и `4.1.0`; они связаны с ранее найденными транзакциями `0307` и `0317`.
Расширенная загрузка не является заменой версии сервиса 3 на более новую.

Это продолжение [исследования сервисов](omron-program-service-versions.md)
от 17 ноября 2026 года. Все действия локальные; vendor API и ПЛК не вызывались.

## Найденные описания моделей

Данные находятся в `C:\Program Files (x86)\OMRON\CX-Server\StaticData\StaticRoot`.
Обычный поиск пропускал файлы этого дерева; `rg --hidden --no-ignore` их находит.
Файлы `StaticInfo.xml` объединяются ссылками `Cxlink`, включая ссылки на группы
`Services[@Name='Local']` и `Services[@Name='Remote']`.

| Проект | Ссылки модели и CPU |
| --- | --- |
| CJ1H-H / CPU65 | Network → CS1-HCommon/VER4_0Common/Cpu/Network |
| CJ1M / CPU21 | Network → Cj1m/Cpu11/Network; Services → VER3_04 → CS1-HCommon/VER4_0Common |

Ethernet перенаправляет группу Services на SPMA. SYSWAY использует свою группу.
В обеих группах наследование доходит до `CS1Common`, где объявлен сервис 3;
в `VER4_0Common` добавлен сервис 532. Remote ссылается на Local.

Для обеих моделей и обоих интерфейсов получены:

| CommandNo | ID | SupportVersion | Класс |
| --- | --- | --- | --- |
| 3 | 3.0.0.0 | 0.0.0 | ProgramDownloadServiceCS1HCPU67SPMA либо SYSWAY |
| 532 | 532.4.1.0 | 4.1.0 | ProgramDownloadExServiceCS1H_V4CPU67SPMA либо SYSWAY |

DLL обоих сервисов — `CXSDI_SeriesCS1MessageServices1.dll`. Исходные `Name`
иногда дополнены пробелами; инструмент сохраняет атрибуты без нормализации и
находит декларации по `CommandNo`.

В отдельном узле `DriverVersionInfo/DriverReleaseVersion` указано `4.1.0`.
Это значение версии драйвера, а не полученная от ПЛК версия firmware/unit.
Конкретный источник ограничения версии при каждом runtime-вызове ещё требует
проверки; простое сравнение с DriverReleaseVersion не выбирает активную операцию.

## Связь с вызывающим кодом CX-Programmer

В стандартной ветви `12610780` CX-P вызывает `CDMDownloadProgram`, который
передаёт логическую команду 3. Альтернативная функция `12613480` формирует
внутренний запрос типа 9 и передаёт номер `0x214 = 532` в цепочку
`CDMPLCCommand`. Это соответствует отдельной XML-записи расширенной загрузки.

Предикат выбора `126992e0` получает объект через `12674e10` и проверяет поле
`+700 / +0x2bc`. Установление этого поля и его связь с реальным состоянием CPU
ещё не прослежены. Наличие обеих деклараций в XML не доказывает, какую ветвь
использовал CX-One при исторической ручной загрузке.

Source SHA-256 CX-P.exe:
`e91f15b8613e56c8f326bc83ce07f5a24b177f5f70a4a445e4eadfa34b0a9eb4`.
Ghidra сохраняет инструкции и pseudo-C обеих функций в текущем исследовательском
каталоге. Сетевых пакетов загрузки этот этап не создаёт.

## Переносимый инструмент

Добавлен `tools/omron-research/inspect_cj1_services.py` на стандартной библиотеке
Python 3.9+. Он читает установленное дерево либо его копию без Windows API,
COM и vendor DLL. Пример из корня репозитория:

```text
python tools/omron-research/inspect_cj1_services.py STATIC_ROOT --model CJ1H-H --cpu CPU65
python tools/omron-research/inspect_cj1_services.py STATIC_ROOT --model CJ1M --cpu CPU21 --network SYSWAY --scope Remote
```

`STATIC_ROOT` — путь к исходному `StaticRoot` либо к сохранённому
`captured-static-root`. Результат JSON содержит декларации сервисов, цепочки
ссылок, версии и SHA-256 всех прочитанных XML. `atOrBelowDriverRelease` —
буквальное числовое сравнение версий. `activeServiceSelected`,
`hardwareQualified`, `writeQualified` остаются false.

Реализован исследованный поднабор формата: directory XML, относительные и
абсолютные Cxlink и простые предикаты `@Name`. Относительная ссылка вычисляется
от самого связанного элемента. Поиск файлов учитывает регистр явно, поэтому
подходит и для копии дерева на файловой системе с чувствительностью к регистру.

Инструмент ограничивает размер XML, число документов и глубину ссылок,
отклоняет циклы, DTD/entities, выход за корень и неоднозначные узлы. Он сообщает
декларации по цепочке, не реализует полное слияние vendor DOM и не обрабатывает
все XPath/Unit overrides. XML-входы для текущих профилей сохраняются отдельно от Git.

## Верификация и оставшаяся работа

Десять тестов на синтетических XML проверяют наследование, Local/Remote,
числовые версии, сохранение пробелов, циклы, опасные пути, неоднозначность и
некорректный XML. Все прошли. Также прошли transfer/Omron CLI tests и сборка
Nautilus после уточнения диагностики плана `0307`.

Сохранены восемь профилей: две модели × два интерфейса × Local/Remote.
Понадобился **21 XML-файл**. Повторный разбор их отдельной копии дал точное
совпадение JSON с чтением установленного дерева. Это проверка переноса входов
на Windows; исполнение инструмента на Linux в этом этапе не проводилось.

Артефакты находятся вне Git в `research/hardware/20261117-cj1-service-xml-01`:
профили JSON, `captured-static-root`, отчёт Ghidra, проверка снимка и manifest.
Проверка снимка и нативных ссылок дала **29/29**. Manifest включает 40 файлов,
SHA-256: `cc29dfaf1c986fbf8553ed1905b9794e436322bc1c29d233abe0ada68d2a2942`.

Далее нужно проследить установку флага `+0x2bc`, ограничение версии в runtime
и окончательную передачу буфера файла во вторую транзакцию. Выбор команды,
stamping заголовка UM и модель восстановления после обрыва остаются
неквалифицированными. Действующая установка по-прежнему только для чтения.
