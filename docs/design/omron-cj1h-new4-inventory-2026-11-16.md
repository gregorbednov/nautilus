# CJ1H: новые проекты, модули и регистрационная таблица

16 ноября 2026 года. Пользователь добавил CXP/OPT `CJ1H Лифт elevator-new4`
и `CJ1M Лифт elevator-new4`, предположительно с актуальными символами/модулями.
Разрешён только опрос CJ1H `10.0.174.37`; `.36` offline и не опрашивался.
Доступ к действующей установке по-прежнему **только чтение**.

## Что сообщает CJ1H

Документированная команда FINS0502 CONNECTION DATA READ вернула последний
блок из четырёх записей (`count/last=84`, hex):

| FINS unit address | Ответ model |
| --- | --- |
| 00 | CJ1H_CPU65H |
| 11 | CJ1W-ETN21 |
| 12 | CJ1W-DRM21 |
| 23 | CJ1W-MAD42 |

Это данные ответа CPU, не извлечение названий из CXP. В адресах11/12 unit
numbers1/2 CPU Bus, в23 — Special I/O number3. Адреса не являются номерами
физических слотов. Обычные дискретные Basic I/O не перечисляются этим классом
адресов, поэтому таблицу0502 нельзя считать полной инвентаризацией стойки.

Источник формата: [Omron W342, разделы5-3-7 и5-3-16](https://assets.omron.eu/downloads/latest/manual/en/w342_cs_cj_cp_nsj_communications_commands_reference_manual_en.pdf?v=9).
Для выполнения использован также локальный `research/W342.pdf`, печатные
страницы181–182,193–194. Запрос0502: `00 19`; ответ и все0201 payload сохранены.

## Полная таблица регистрации I/O

Дважды прочитаны **все1280 слов /2560 bytes** области8012 командой0201,
блоками498+498+284 слова. Проверены area/address/count echoes, длины и
конечный флаг; копии совпали. SHA-256:
`63ebaaf0b8a442875b7880eae77f0d892f41c3e897b2d7f80489868546c6a786`.

В `Resource[0].PLC.IOTable.Data` нового CJ1H CXP найдено полное побайтовое
совпадение всей области: после40-byte сохранённого префикса и перестановки
двух байтов каждого16-bit слова. Найдено единственное matching window,
не только совпадение первых ID. Остальной196-byte хвост CXP не выдаётся
за часть области8012; его формат ещё не квалифицирован.

Та же регистрационная таблица совпадает и со **старым** CJ1H CXP из projects.
Таким образом, подтверждено соответствие таблицы регистрации в обоих файлах
прочитанной таблице CPU; проверка не выбирает новый проект как единственный
актуальный исходник.

Область8012 — **зарегистрированная конфигурация**, которая может быть
загружена. Её совпадение не является независимым доказательством физического
наличия каждого Basic I/O модуля. Команда0502 даёт отдельные сведения о
перечисленных выше устройствах, но не покрывает весь физический rack/slot
состав. До/после: status5, mode4, fatal0, nonFatal0. Отсутствие ошибок не
заменяет полную проверку физических модулей и назначений клемм.

## PLC Setup

Дважды прочитана полная8010:512 слов /1024 bytes, все нули; копии совпали,
SHA-256 `5f70bf18a086007016e948b04aed3b82103a36bea41755b6cddfaf10ace3c6ef`.
Нулевая область встречается во множестве окон сохранённого Settings.Data,
поэтому её совпадение не использовано как доказательство расположения полей
или полного соответствия CXP Settings. Семантика настроек пока не восстановлена.

## Символы в новых файлах

| Источник | Глобальные строки | Локальные строки Program0 / Program1 |
| --- | --- | --- |
| Новый CJ1H CXP | 16 | 10 /68 |
| Новый CJ1M CXP | 16 | 68 /31 |

Подсчитаны строки деклараций, включая возможные адресные аннотации, а не
количество независимо подтверждённых сигналов. В новых CJ1H/CJ1M глобальные
таблицы совпадают с прежними после исключения source-line номеров. Локальная
таблица Program1 CJ1H и Program0 CJ1M отличается; прочие сравниваемые локальные
таблицы совпали. Это сравнение объявлений name/address/type/aux/flags/scope,
не утверждение о полном совпадении комментариев или исполняемой логики.

Имена, типы и привязки извлечены из CXP и сохранены JSON. **Из CPU таблица
символов не получена**, поэтому актуальность имён и соответствие физическим
датчикам/исполнителям не подтверждены. Факт чтения CIO/D/W по числовому адресу
сам по себе не доказывает название или назначение сигнала. OPT в качестве
аппаратного свидетельства не использовался. CJ1M проверен только offline.

SHA-256 новых CXP:

## Программа снова изменилась между сессиями

Пользователь подтвердил, что между сообщениями было занятие на контроллерах
и могли выполняться сторонние загрузки. Новые две UM-копии совпали между собой:
2716 bytes, SHA-256
`d54d9fcb0e4c5f6fb95bc16c31b07fd55a880982835d31b6676af744a1c34a46`.
Сейчас одна задача256,24 code words, без FB. Это отличается от прежнего
4604-byte снимка после ручной загрузки нашего проекта. Имя задачи сохранено
сырыми байтами `cdeee2e0ffc7e0e4e0f7e031`, без автоматического выбора кодировки.

Новый CJ1H CXP отдельно скомпилирован независимым CLI с прежним явным JSON:
4604 bytes, SHA-256
`97495506fc1e61bf1a2b19c38890d1659ff13ea21caca1740d3520589e164ef4`.
Следовательно, сейчас этот CXP **не соответствует считанному UM**. Ранее
подтверждённое совпадение старого CXP с4604-byte UM остаётся корректным
историческим результатом, но не текущим состоянием устройства. Любые будущие
сверки привязывать к времени/хешу, не считать программу неизменной между сессиями.
