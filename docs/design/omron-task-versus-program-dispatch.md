# Полная передача UM и отдельная передача задач

Продолжение: [writer маркера/380-byte блока и реализация plain OBJ](omron-plain-object-envelope.md).
Ниже сохранено состояние до обнаружения writer12685840.

17 ноября 2026 года. Продолжение [анализа writer](omron-n1-writer-and-protected-file.md).
Проверка границ функций уточнила цепочку: вызов `12612097` принадлежит
**отдельной функции12611fd0**, которую диспетчер12610780 вызывает по12610bbd.
Предыдущая формулировка «12612097 внутри диспетчера» была неточной и исправлена.

## Подтверждённая цепочка задач

```text
12610780, state8
  → 12610bbd: CALL12611fd0
      → 12612097: CALL12699520
          → EncryptUMObject через ранее исследованный helper
```

В state8 диспетчер имеет две ветви: обработку элементов таблицы с шагом0x2c
и полную передачу по пути из поля+78. В первой ветви в12611fd0 передаются
поля элемента+4 и+0c. В helper первое используется как имя файла,
второе сохраняется в16-bit поле+20a внутреннего запроса. Именованный thunk
`1285abf2 → IAT12b2269c` разрешается в
`PLC_KBase::GetTaskConfigurationTable(int)`; результат помещается в+20c.
Это подтверждает принадлежность ветви отдельной программе/задаче.

В зависимости от owner+428 и+434 helper выбирает:

| Условие | Логический сервис | XML Name |
| --- | --- | --- |
| хотя бы одно поле нулевое | 0x1cf =463 | CDM_DOWNLOAD_TASK |
| оба поля ненулевые | 0x20e =526 | CDM_DOWNLOAD_TASK_EX |

Это условие именно этого helper. Оно ещё не сведено к полной семантике
IsExtendedProtect; нельзя автоматически заменять одну проверку другой.
Для вызова12699520 здесь явно передаётся третий stack аргумент1, поэтому
ветвь уменьшения аргумента на0x400/установки bit8000 из предыдущего отчёта
**в этом вызове не выполняется**.

В той же функции есть `PUSH0x214` при выделении внутреннего буфера.
Это размер532 bytes, а не выбор сервиса532. Поиск числовых констант без
контекста аргументов может смешивать две разные операции.

## Чем это отличается от полной передачи

Полная ветвь того же диспетчера12610780 проверяет126992e0:
нулевой результат ведёт в `CDMDownloadProgram` (service3/0307), ненулевой —
в12613480 (service532/0317). Это ранее подтверждённая отдельная цепочка.
Новый caller12611fd0 и его463/526 не заменяют эту проверку.
FINS-команды task-сервисов на этом этапе не разбирались.

Дополнительно сохранены12694f80 и12699b90. Первый имеет guard descriptor+44
bit20 и формирует CDM-запрос; второй работает с данными защиты и UI/helper
операциями. Они не доказаны как место создания380-byte обёртки.
Pseudo-C с `unaff_*` не используется как точная спецификация сигнатур.

## Переносимый инструмент

`tools/omron-research/inspect_cj1_services.py` теперь принимает
`--family program|task`, по умолчанию program. Для program сохраняет прежний
JSON целиком и поле `programServices`. Для task выдаёт `taskServices`,
фильтруя только CommandNo463/526 по той же цепочке Cxlink.

```sh
python -B tools/omron-research/inspect_cj1_services.py STATIC_ROOT --model CJ1H-H --cpu CPU65 --family task
python -B tools/omron-research/inspect_cj1_services.py STATIC_ROOT --model CJ1M --cpu CPU21 --network SYSWAY --scope Remote --family task
```

Реальные XML обоих профилей, ETHERNET/SYSWAY и Local/Remote, содержат:

- 463, SupportVersion2.0.0, DownloadTaskServiceCS1H_V2CPU67SPMA/SYSWAY;
- 526, SupportVersion4.1.0, DownloadTaskExServiceCS1H_V4CPU67SPMA/SYSWAY;
- обе записи используют CXSDI_SeriesCS1MessageServices9.dll.

Версии относятся к сервисам драйвера. Наличие XML не доказывает выбор операции,
совместимость CPU или разрешение записи. Все qualification/selection flags
остаются false; сетевых операций и vendor execution инструмент не содержит.
